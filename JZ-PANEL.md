# J&Z Panel

J&Z Panel is a redesigned Minecraft server management interface built directly on the supplied panel source. The existing Laravel APIs, authentication, permissions, server APIs, file APIs, backups, schedules, databases, WebSocket console and Wings integration are retained as the infrastructure layer.

## Development

The supplied manifests are authoritative:

- PHP: `^8.2 || ^8.3`
- Laravel: `^12.60.0`
- Node.js: `>=22`
- React: `^16.14.0`
- TypeScript: `~5.1.0`
- Tailwind CSS: `^3.0.24`

Install frontend dependencies with the repository's package manager and run the existing scripts:

```bash
yarn install
yarn run tsc
yarn run lint
yarn test
yarn run build:production
```

## Production installer

Run from the root of this source tree:

```bash
sudo bash install.sh
```

The installer provides:

1. Panel
2. Wings
3. Panel + Wings

It detects Debian/Ubuntu family systems and amd64/arm64 architecture, installs dependencies based on the repository requirements, configures MariaDB/Redis, builds the frontend, runs migrations, configures queue/scheduler services, and can configure Nginx/Apache and Let's Encrypt.

For automation:

```bash
sudo JZ_DOMAIN=panel.example.com \
  ADMIN_EMAIL=admin@example.com \
  ADMIN_PASSWORD='use-a-strong-password' \
  bash install.sh --panel --non-interactive
```

Do not put real credentials in shell history or CI logs. Prefer secret/environment management in automated deployments.

## Management CLI

```bash
jz-panel status

jz-panel logs
```

## Registration

Public registration is implemented but can be disabled with:

```dotenv
APP_REGISTRATION_ENABLED=false
```

When enabled, registration is throttled and uses the existing reCAPTCHA middleware when reCAPTCHA is configured. Passwords require at least 12 characters plus mixed case and numbers. New accounts are never granted administrator privileges.

## Wings

The panel source supplied for this build does not contain the Wings daemon source. The installer therefore installs the Wings release binary and systemd service when requested. Node configuration remains generated by the panel and must be placed at `/etc/pterodactyl/config.yml` before Wings can start on a new node.
